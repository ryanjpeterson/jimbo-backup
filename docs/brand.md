# jimbo-backup brand

jimbo-backup's dashboard is built on **jimbo.ui** (repo `jimbo-ui`), Ryan's shared
brand and UI system
([github.com/ryanjpeterson/jimbo-ui](https://github.com/ryanjpeterson/jimbo-ui)).
The rules — theme engine, templates, tokens, type, shell, components and
patterns — live in its guide (`skills/jimbo-ui/guide.md`). The version this app
is on is in [`jimbo-ui.json`](../jimbo-ui.json); to pick up a newer one, ask
Claude to "update to the latest jimbo-ui".

## What belongs to this app

| What | Where |
| --- | --- |
| Name `jimbo.backup` (header text; the dot takes the accent), default colours — jimbo-ui's **Deep sea** template (accent `#3DFFC5`, highlight `#FF7A59`, support `#9BB0FF`, background `#071A1F`), storage prefix `jimbobackup` | `web/src/lib/brand.config.ts` |
| Default tokens | `web/src/styles/tokens.css` (generated by jimbo-ui's `scripts/tokens.mjs`) |
| Tabs: Home · Runs · Settings | `web/src/App.tsx` |
| UI kit | `web/src/components/ui/jimbo-kit.tsx` is an exact copy of jimbo.ui's reference kit (update by copying); `kit.tsx` re-exports it and adds this app's pieces — `VolumeChip`, `BackupRow`, `RunRow`, `LogSheet`, `KeyValue`. Rows inside `divide-etched` lists use `<article>` or `<p>`, not `<div>`: the rule also draws lines between the children of a `<div>` row |
| Backup statuses on jimbo-ui's tones | `STATUS` in `web/src/lib/backups.ts`: backed up = accent, running = yellow, failed = red, skipped and never run = muted. Errors, and stale copies of scheduled jobs on always-there drives, use the highlight. A running dot also pulses (the kit's `LIVE`): with a yellow accent, done and running would otherwise be the same colour |
| Theme storage | `app/server.js` — `GET /api/public/theme`, `PUT`/`DELETE /api/admin/theme`, stored in `theme.json` next to `state.json` on the logs volume. Accepts and returns the optional `infer`, `vibrancy`, `contrast`, `fonts` and `backdrop` (including its `contrast` and `saturation`), checked for shape and range |
| jimbo-ui config section | `/jimbo-ui` (`web/src/routes/JimboConfigPage.tsx` and `routes/config/`), linked from Settings. `auth` is `none` in `jimbo-ui.json`, so `canConfigure` is always true. The Style guide tab adds a *This app* block |
| Kit override | `KeyValue` in `kit.tsx` replaces the kit's: the kit's is a `<div>`, which jimbo-ui's `divide-etched` draws a stray line inside. Recorded under `components.overrides` in `jimbo-ui.json` |

## Where this app differs from the reference

- **The default fonts are bundled** (`@fontsource/*`, imported in
  `web/src/main.tsx`) instead of loaded from Google Fonts, so the dashboard
  works with no internet. Any other font picked in the Brand page's *Type*
  section loads from Google Fonts like in every jimbo.ui app; offline, it falls
  back to the system font.
- **No favicon upload.** The config section's Brand tab drops that section and
  the server doesn't implement the favicon routes; the built-in favicon still follows the
  theme.
- **No auth on the theme routes.** Nothing in this dashboard has accounts — it's
  reachable only on the home network or tailnet, where anyone can already start
  a backup — so "admin" routes are open like the rest.
- **No PWA manifest or app icons.** The installed-app meta tags are there, but
  no generated icons.

## Rules for changing the look

- Files whose header says **"Part of jimbo-ui (foundation)"** are copied from
  jimbo-ui on every update — don't edit them here. Change jimbo-ui, release,
  then update.
- Changes to this app's own UI (pages, the kit's app pieces) are made here. If
  one should apply to every app, release it in jimbo-ui too, as a generic
  pattern with neutral names — never this app's code or content.
